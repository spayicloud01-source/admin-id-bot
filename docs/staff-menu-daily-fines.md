# Staff rich menu and daily fine receipts — release 2026.10.03-130

After owner approval, fine receipts append customer history and a calendar-cell note, and add the amount to the unique row labeled `ค่าปรับ` in the same sheet and receipt-date column. Existing numeric totals are retained. Confirmed live layouts: both active sheets have the label in N27; v3/10-69 AQ2 is 29 September 2026, so receipts for that date accumulate in AQ27. The code resolves the label and date dynamically rather than fixing AQ for every date.

Rent cells, cycle totals, and due dates stay unchanged. Re-approving a completed receipt does not add it again. Cancellation of a new receipt subtracts its amount and removes its own note markers, preserving other customers' receipts and manual opening balances. Formula totals, ambiguous/missing labels, moved identities, or missing cancellation markers fail closed. Existing release-129 receipts are not automatically backfilled into daily totals.

The six-button per-user staff rich menu provides receive rent, receive fine, review queue, customer lookup, today's receipts, and a website link. Only authenticated staff with payment permission are linked; the default customer menu is not changed. The website button uses a URI action, not the similarly named bot master-switch command. Existing permissions on reports and review actions remain enforced.

Today's report separates approved rent and fines and excludes cancelled/unapproved receipts. Fine dates come from the actual receipt-date field; rent dates match the source calendar write date. Reports remain owner-only.
